Methods & reproducibility

Release status: v0.2 review build. Brussels IBSA social indicators are identified but not yet spatially integrated. No vulnerability-informed rankings are claimed in this release.

Data versions and boundaries

  • Amsterdam: PDOK administrative boundary; CBS neighbourhood layer labelled 2025 in the export script.
  • Brussels: UrbIS regional boundary and Brussels monitoring neighbourhoods; exact neighbourhood vintage to verify against source GeoPackage.
  • ESA WorldCover 2021 (10 m); Copernicus imperviousness 2021 (10 m); GHSL GHS-POP 2020 (100 m).
  • Landsat 8/9 Collection 2 Level 2: June–August 2019–2023.

The source years differ. Scores compare cells within each city, not a common observation year or directly comparable city outcomes. Provider reuse terms apply; the derived web files have no asserted blanket open licence.

Processing and code

  1. Project source rasters and boundaries to a common analytical CRS.
  2. Intersect with a 500 m grid, calculate land cover and population indicators, then normalise within each city.
  3. Apply four disclosed weight combinations and their median; aggregate neighbourhood summaries by cell overlap area.
  4. Validate association with Landsat surface temperature using Random Forest and five spatial folds.

The public export and validation code produces web files from a source GeoPackage absent from the repository. Full upstream raster processing code, input snapshots, model seed and environment are not deposited. This is a partial reproduction path.

Limitations and planned checks

  • MAUP: grid size and neighbourhood boundaries can change rankings.
  • GHSL 2020 population is modelled, not observed per cell.
  • Indicators span 2019–2025, not one year.
  • Social vulnerability is incomplete in the model.
  • No uncertainty intervals for priority scores.
  • Planned: Spearman and Kendall correlations and high-priority quantile overlap under alternative weights and spatial units.
